# É7 Agenda de turnos — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agenda where therapists see and manage their own appointments and admins see and manage everyone's, with a calendar tab and an assigned-appointments (cards) tab.

**Architecture:** New backend feature package `appointment` (entity + Flyway V9 with exclusion constraints, Strategy for role visibility, Chain of Responsibility for booking rules, availability service) exposed under `/api/appointments` and `/api/agenda/therapists`. New Angular feature `features/agenda` with hand-made calendar components; pure layout/date logic lives in plain TS files with specs.

**Tech Stack:** Java 21, Spring Boot 3.5, JPA/Hibernate, Flyway, Postgres 15 (`btree_gist`), Testcontainers; Angular 21 standalone + signals, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-05-agenda-design.md` (mockups: `docs/mockups/h7.1-agenda/`, read the README and the `source/*.dc.html` files for exact texts, sizes and colors).

## Review Focus

- Two bookings for the same therapist and slot at the same moment: the second must get `THERAPIST_BUSY` (409), never 500 — pinned in Task 5 by translating the exclusion-constraint violation (`AppointmentServiceImplTest.exclusionViolationsBecomeConflicts`).
- Back-to-back appointments (10:00–10:30 then 10:30–11:00) must be allowed — pinned in Task 1 (DB) and Task 3 (chain).
- Rescheduling an appointment onto (part of) its own current slot must be allowed — pinned in Task 4 (`excludeAppointmentId`) and Task 5 (PUT test).
- A therapist calling `GET /api/appointments?therapistIds=<other>` or `PUT/DELETE` on another therapist's appointment must not see/modify it — pinned in Task 5.
- A 60-min booking starting 19:30 (ends 20:30) and any Sunday booking must be rejected with `APPOINTMENT_OUTSIDE_HOURS` — pinned in Task 3.

```sql
-- É7: appointments. Exclusion constraints keep one appointment per therapist and per patient at any time.
CREATE EXTENSION IF NOT EXISTS btree_gist;

CREATE TABLE appointment (
    id           BIGSERIAL    PRIMARY KEY,
    therapist_id BIGINT       NOT NULL REFERENCES app_user (id),
    patient_id   BIGINT       NOT NULL REFERENCES patient (id),
    diagnosis_id BIGINT       REFERENCES diagnosis (id),
    start_at     TIMESTAMP    NOT NULL,
    end_at       TIMESTAMP    NOT NULL,
    notes        VARCHAR(500),
    created_at   TIMESTAMPTZ  NOT NULL,
    CONSTRAINT ck_appointment_range CHECK (end_at > start_at),
    CONSTRAINT ex_appointment_therapist_overlap EXCLUDE USING gist (therapist_id WITH =, tsrange(start_at, end_at) WITH &&),
    CONSTRAINT ex_appointment_patient_overlap EXCLUDE USING gist (patient_id WITH =, tsrange(start_at, end_at) WITH &&)
);
CREATE INDEX ix_appointment_start ON appointment (start_at);
```

Controller routes: `GET /api/appointments?from&to&therapistIds` (`@RequestParam(required=false) Set<Long> therapistIds`), `GET /api/appointments/{id}`, `GET /api/appointments/availability?therapistId&patientId&date&durationMinutes&excludeAppointmentId` → `List<SlotResponse>`, `POST /api/appointments` (201), `PUT /api/appointments/{id}`, `DELETE /api/appointments/{id}` (204), `GET /api/agenda/therapists`. All take `@AuthenticationPrincipal AuthenticatedUser actor`.

Service rules:
- `list`: `to` < `from` or more than 42 days → `APPOINTMENT_RANGE_TOO_LONG`; spec `startAt >= from 00:00 and startAt < to+1 00:00` plus `therapist.id in visible` when the policy returns a set; order by `startAt`, then `id`. Fetch therapist/patient/diagnosis with an entity graph to avoid N+1 (`@EntityGraph(attributePaths = {"therapist", "patient", "diagnosis"})` on `findAll(Specification, Sort)` override).
- `book`/`reschedule`: duration via `AppointmentDuration.fromMinutes` else `APPOINTMENT_DURATION_INVALID`; resolve therapist (`UserRepository.findById` → `USER_NOT_FOUND`), patient (`PATIENT_NOT_FOUND`), diagnosis (`DIAGNOSIS_NOT_FOUND`); reschedule loads the appointment (`APPOINTMENT_NOT_FOUND`) and first checks the actor can manage its **current** therapist (so a therapist cannot move someone else's appointment to herself); build `AppointmentDraft`, run the chain, save with `saveAndFlush` inside `try`; catch `DataIntegrityViolationException` and map by message containing `OverlapConstraint.THERAPIST/PATIENT.getConstraintName()` → `THERAPIST_BUSY` / `PATIENT_BUSY`, otherwise rethrow as `InternalSystemException`.
- `cancel`: load (`APPOINTMENT_NOT_FOUND`), `checkCanManage(actor, therapist)`, delete.
- `AgendaTherapistServiceImpl`: admin → `userRepository.findAllByOrderByFullNameAsc()` sorted active first; therapist → only herself. Color = `TherapistColor.forUser(id).getIndex()`.
