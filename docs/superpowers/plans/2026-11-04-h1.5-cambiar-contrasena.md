# H1.5 Cambiar mi contraseña — plan

**Historia:** Como usuario quiero cambiar mi contraseña para mantener mi cuenta segura.
- Pide la contraseña actual y la nueva (mínimo 8 caracteres).
- Si la actual es incorrecta, se rechaza el cambio.

**Mockup:** `docs/mockups/h1.5-cambiar-contrasena/mobile.png` (fuente `source/app/M-Password.dc.html`, con el error de contraseña actual). Los accesos están en "Más" → "Mi cuenta" y en el pie de `SideNav.dc.html`.

## Backend
- `PUT /api/auth/password` (cualquier usuario autenticado), body `ChangePasswordRequest(currentPassword, newPassword)`; responde 204.
  - `newPassword`: entre 8 y 72 caracteres (72 es el límite de BCrypt).
- `AuthService.changePassword(userId, request)`:
  - Si la contraseña actual no coincide, responde `CURRENT_PASSWORD_INCORRECT` (422, "La contraseña actual no es correcta."). Es 422 y no 401 para que el frontend no cierre la sesión.
  - Si el usuario no existe o está inactivo, responde `AUTHENTICATION_REQUIRED` (igual que `/me`).
- `User.changePasswordHash(hash)`. Sin cambios de esquema (`supabase/init/*` igual).
- La sesión actual sigue abierta: el JWT no depende de la contraseña.

## Frontend
- Ruta `/cambiar-contrasena` (`ChangePasswordPage`) dentro del shell, para cualquier rol.
- Formulario: contraseña actual y nueva, con 4 barras de progreso y el contador "Mínimo 8 caracteres (n/8)", y el botón "Guardar nueva contraseña".
  - **Error 422:** banner "La contraseña actual no es correcta / No se guardó ningún cambio." y el campo actual en rojo.
  - **Éxito:** banner de confirmación "Tu contraseña se actualizó" y el formulario se vacía. El mockup no tiene ese estado; se usa el estilo `alert--info`.
- `AuthService.changePassword(current, next)`.
- Accesos: "Cambiar contraseña" en "Más" → "Mi cuenta" y en el pie de la side nav.
- Tokens nuevos: `--color-warning` (barras con menos de 8 caracteres) y `--color-track`.
