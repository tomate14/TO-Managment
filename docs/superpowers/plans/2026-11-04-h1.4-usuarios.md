# H1.4 Gestión de usuarios — plan

**Historia:** Como admin quiero crear, editar y desactivar usuarios para controlar quién accede.
- Alta con email (único), nombre, contraseña inicial y rol.
- Edición de nombre y rol. El email no se puede repetir (y no se edita).
- Desactivar a un usuario le impide loguearse. La admin no puede desactivarse a sí misma.

**Mockups:** `docs/mockups/h1.4-usuarios/mobile-listado.png`, `mobile-nuevo-usuario.png` (fuentes `source/app/M-Users.dc.html`, `M-UserNew.dc.html`); "Administración" en `M-More.dc.html` y `SideNav.dc.html`.

## Backend
- API bajo `/api/users`, solo `ADMIN` (`@PreAuthorize`; el 403 sale por `GlobalExceptionHandler` → `ACCESS_DENIED`):
  - `GET /api/users` → `UserResponse[]` (id, email, fullName, role, active), por nombre.
  - `GET /api/users/{id}` → `UserResponse`.
  - `POST /api/users` (`CreateUserRequest`: email, fullName, password 8–72, role) → 201.
  - `PUT /api/users/{id}` (`UpdateUserRequest`: fullName, role).
  - `PATCH /api/users/{id}/active` (`ChangeUserActiveRequest`: active).
- `UserManagementService` (interfaz) + `UserManagementServiceImpl`.
- Nuevos `ErrorCode`: `USER_NOT_FOUND` (404), `USER_EMAIL_TAKEN` (409, "Ya hay un usuario con este email."), `SELF_DEACTIVATION_FORBIDDEN` (422), `SELF_ROLE_CHANGE_FORBIDDEN` (422).
  - **Decisión:** la admin tampoco puede cambiar su propio rol, por la misma razón que no puede desactivarse: no quedarse sin administradoras.
- `User` suma `updateProfile(fullName, role)` y `changeActive(active)`.
- Sin cambios de esquema (la tabla `app_user` ya tiene todo): `supabase/init/*` sin cambios.
- **Limitación conocida (pendiente):** el JWT no se revalida contra la base, así que una persona desactivada o con rol cambiado conserva su token hasta que vence (`JWT_EXPIRATION_MS`).

## Frontend
- Rutas (dentro del shell, con `adminGuard`): `/usuarios`, `/usuarios/nuevo`, `/usuarios/:id`.
- `UsersService` (HTTP).
- `UsersPage`: tarjetas con iniciales, nombre ("(vos)" en la propia), email, editar, badges de rol y estado, y switch para activar/desactivar ("No podés desactivarte" en la propia).
- `UserFormPage` (alta y edición): nombre, email (deshabilitado al editar), contraseña inicial (solo alta, mín. 8), rol con dos opciones; "Cancelar" y "Crear usuario"/"Guardar cambios". `USER_EMAIL_TAKEN` → error en el campo email.
- Navegación solo para admin: sección "Administración" → "Usuarios" en la side nav y en "Más" (con "Esta sección solo la ven las administradoras."). "Catálogos" llega con É2.
- Tokens nuevos: `--color-success`, `--color-success-bg`, `--color-neutral-bg`, `--color-switch-off`, `--color-primary-tint`.
